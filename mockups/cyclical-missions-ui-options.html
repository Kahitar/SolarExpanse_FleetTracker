Cyclical Mission UI Options

Visual summary for improving the game's native cyclical mission overview side panel.

Primary target: adapt the existing native cyclical mission panel. A separate FleetTracker panel is only a fallback if the native UI is too brittle.

1. Patch native rows

Preferred if stable

What changes

  • Keep the native side panel and entry point.
  • Reformat each mission into compact route cards.
  • Preserve native edit/cancel actions if safe.

Pros

  • Directly improves the original game overview.
  • Best player workflow fit.

Risks

  • Depends on private UI methods and row hierarchy.
  • More fragile across game updates.

2. Replace panel content

Best fallback

What changes

  • Keep the native panel shell.
  • Hide original content container.
  • Inject a custom scroll view sized to the side panel.

Pros

  • Still feels native.
  • More control than editing old rows.

Risks

  • Edit controls may need later reintegration.
  • Needs reliable cleanup on reopen.

3. Separate FleetTracker panel

Safety fallback

What changes

  • Add a new FleetTracker dashboard.
  • Leave the original game panel untouched.
  • Use a wider layout if needed.

Pros

  • Lowest risk to game UI.
  • Maximum layout freedom.

Risks

  • Does not directly fix the native overview.
  • Duplicates mission information.

First

Inspect game metadata and runtime hierarchy for the native cyclical mission panel, row prefab, and rebuild methods.

→

Then

Prototype compact side-panel route cards as a read-only view, preserving native edit actions only when safe.

→

Fallback

If native rows are brittle, replace the native panel content area. Use a separate FleetTracker panel only as last resort.

Recommended direction

Target the native side panel first. The improved layout should fit within the game's existing narrow panel, using stacked route cards rather than a wide table.

  • One route per card: A ↔ B.
  • Compact status badge: Active, Paused, Ending, Done.
  • Craft line: names plus count.
  • Two cargo lanes: A→B and B→A.
  • Cycle count/progress when available.
